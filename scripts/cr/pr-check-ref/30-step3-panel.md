# /pr-check reference: step 3.0: critic panel first pass

3. **Cross-model finding pass (critic panel), then adjudication.**

   **Operator ruling 2026-09-21: the operator authorises sending review diffs to Codex from workers.** The external-critic scripts below (`panel-first-pass.sh`, `docs-audit-panel.sh`, plus step 2's `doc-freshness-advisory.sh` and `known-findings.sh --diff`) are allow-listed for the worker profiles as literals, so a denial on one of them most likely means the call was not spelled as its literal (see the fence contract's himmel-lane spelling) — check the spelling first. A denial that names a deny rule or a policy restriction is not a spelling problem: stop and report it, never respell around it, and never skip the lane silently.

   **Step 3.0 — critic panel first-pass (decimal substep, runs BEFORE any Agent dispatch):**

   `/pr-check` runs the cross-model panel (~2min — bounded by the 240 s per-member `CRITIC_TIMEOUT_SECS`, but ONLY when the `timeout` binary is present; without it each member runs unbounded — see step 3.0's hang-protection note) by **default**. Control via `CR_PROFILE`.

   **The default is the PAID codex critic — there is no free anchor (operator decision: accept paid-by-default).** The free lane was **removed deliberately** — it made more trouble than it was worth: gptoss + kimi were dropped 2026-07-03 (12% / 13% ledger agreed-rate — noise), and the surviving qwen3coder anchor kept erroring rc=1. Paid-by-default is the intended posture, not drift; only these docs had lagged. `critics.json` today contains exactly one row — `codex` / `gpt-6.2-sol`, tier `paid`. So an unset `CR_PROFILE` resolves to zero free rows and falls back to the paid anchor: **a default `/pr-check` that actually runs the panel consumes the OpenAI usage bank.** The panel is skipped (no spend) when the diff is empty or `CR_PROFILE=none`; note the triviality gate does NOT save you here, since it only fires when `paid` is already in the tier filter and the default filter is `free`. Use `CR_PROFILE=none` for instant claude-only when spend is not wanted.

   **Structural note: do NOT hand-compute a tier filter.** `CR_PROFILE` is loaded from the primary checkout's `.env` and exported; `critic-panel.sh` resolves its tiers **from `CR_PROFILE` itself** and treats it as authoritative (it wins over any `CRITIC_PANEL_TIERS`). This closes a drift where a run scoped the panel to free-only (silently dropping the paid codex critic) by hardcoding `CRITIC_PANEL_TIERS=free`. `panel-first-pass.sh` loads and exports `CR_PROFILE` and honours the `none` skip; the panel does the rest. Do not reintroduce a tier filter into the runbook. Semantics the panel implements:
   - `CR_PROFILE` unset/empty → **DEFAULT**: tier filter `free`, which currently matches NO rows in `critics.json` → the panel falls back to the **paid** codex anchor. Print note: "Default cross-model CR — no free critics registered, using the PAID codex anchor (~2min; set CR_PROFILE=none for instant claude-only)."
   - `CR_PROFILE=none` → **claude-only** (skip panel entirely, in THIS runbook); print a one-line note and skip.
   - `CR_PROFILE=thorough` → panel tiers `free,thorough` (equals the default while critics.json defines no thorough-tier rows; the branch is kept so heavier critics can slot back in).
   - `CR_PROFILE=paid` → the **paid escalation** critic (codex / `gpt-6.2-sol` via hermes `openai-codex` OAuth) — for high-stakes PRs or when the free panel disagrees. Consumes your OpenAI usage bank. Combine with the free panel via `CR_PROFILE=free,paid`. **Triviality gate:** when the diff is classified *trivial* (docs-only, or a ~one-line non-safety code change — ≤2 changed diff lines, i.e. one modified line), the panel drops the paid tier to save codex spend — set `CR_TRIVIALITY_OVERRIDE=full` to force the full panel regardless. If `paid` was the ONLY requested tier, the panel does not substitute free: it keeps exactly ONE external critic instead of degrading to claude-only, so the delta still gets a real `avail ok` row and the marker stays clearable, with or without `CR_REQUIRE_CROSS_MODEL`.
   - any other value → passed through as the tier filter verbatim (advanced/custom, e.g. `free,paid`).

   Per-member hang protection: `CRITIC_TIMEOUT_SECS` — default **240 s**, which is ALSO the fallback when the supplied value is non-numeric or ≤0 (the panel warns and uses 240 rather than failing). It was raised from 150 s after codex + qwen3coder were seen clipping at 150 s. It **needs the `timeout` binary but does not require it**: when `timeout` is absent the panel prints "per-member hang protection disabled" and runs each member **unbounded** (`critic-panel.sh:90-92`). `CR_PROFILE=none` skips the panel entirely.

   Total-panel hang protection: `CRITIC_PANEL_TOTAL_TIMEOUT_SECS` — default **900 s**, `0` disables. `CRITIC_TIMEOUT_SECS` bounds ONE member; this bounds the run as a whole, so N members each clipping their own budget cannot hold you for N×240 s. It works three ways: the deadline is checked **between** members (remaining critics are then reported `unavailable … reason=panel-deadline` — a MISSING signal, never a clean one); each member's own timeout is clamped to what is left of the budget **minus the `timeout -k` SIGKILL grace** (`CRITIC_KILL_GRACE_SECS`, 5 s) — reserving the grace so nominal + grace still fits inside the remainder, since a member that ignores SIGTERM spends both — so a member starting just before the deadline cannot overrun it by a further 240 s; and the same applies inside a member's **fallback chain**, which refuses to start another candidate once the panel budget is spent — without that, a `trigger=any` primary that timed out entered its chain with a *fresh* deadline built from the full per-member timeout and could run past the advertised total. Be precise about the limit, in both directions: the clamp needs the `timeout` binary, so on a host without it a member already in flight still runs unbounded and the effective guarantee degrades to "no NEW member starts after the deadline"; and even WITH the clamp, the last clamped member can still end up to **one** grace period past the deadline (one grace, not grace × n_members — `_panel_remaining` recomputes from wall clock per call, so an earlier member's overrun is already absorbed into the next member's remainder).

   > **Never wait unbounded on a backgrounded panel.** A backgrounded Bash task's `timeout` parameter does not bound a detached task, and a panel that dies before its first `echo` produces no output to wait for.
   >
   > When you background the panel, poll it with a hard deadline instead of sleeping on it:
   >
   > - `critic-panel.sh` emits `critic-panel.sh: START pid=…` as its **first** line, before any sourcing or subshell. Use it as the liveness probe:
   >   - **beacon present** → the panel is running; let its own timeouts bound it.
   >   - **beacon absent after ~60 s** → the wedge is BEFORE the panel (the `bash -c -l` login-shell wrapper, profile init under a detached/no-tty handle, or your own redirect). It will not recover. Kill the `bash.exe` PIDs — the task reaps in ~1 s and you lose nothing, because 0 bytes is 0 bytes.
   > - Then fall back to `CR_PROFILE=none` (claude-only) for that round and **say so in the PR body**, rather than stalling.
   >
   > **Do not read liveness from the transcript's file mtime** — it kept advancing while the content was frozen and byte-identical, which is exactly what made a prior status check report "wrote 45 min ago" on a 3-hour-dead session. The reliable test is **max in-content `timestamp` + file size**.

   **The first pass now lives in `scripts/cr/panel-first-pass.sh`.** The fence it replaces tripped the worktree-isolation guard on several shapes at once — a project-directory env-var reference, a `"$var"/literal` split-quoted path, `${var}` braced expansion, and runtime values as dash-flag operands — so it could never run in an isolated session. Everything the fence did, the script still does, in the same order: resolve the protected default branch (main OR master); load and export `CR_PROFILE` from the PRIMARY checkout's `.env` (process env wins) WITHOUT hand-computing a tier filter, because the panel derives its tiers from `CR_PROFILE` itself and treats it as authoritative (hand-scoping the tier is what drifted the panel to free-only); honour the `CR_PROFILE=none` claude-only skip and the empty-diff skip; run `critic-panel.sh` with `CR_USAGE_LOG=1` (estimated-usage ledger rows); retry ONCE through `rtk proxy git diff` when the first attempt failed; and fail OPEN to claude-only on every other failure. Substitute step 0's printed `head=` and `branch=` literals — the script never re-derives them (review the SHA the ledger will certify, not live HEAD, and pin the branch too, because a SHA pin alone would pass a switch to a different branch sitting at the same commit):
   ```bash
   bash "<himmel_dir>/scripts/cr/panel-first-pass.sh" --head <head> --branch '<branch>'
   ```

   **On `outside-pr: yes` (step 0), add `--full` and name the PR's head branch (`headRefName`):**
   ```bash
   bash "<himmel_dir>/scripts/cr/panel-first-pass.sh" --head <head> --branch '<headRefName>' --full
   ```
   Items 16b and 16f key on `headRefName`, so a local branch of another name records rows they never read. `--full` makes rounds 1-3 review the whole branch, never a delta, and never lifts the round cap. Past the cap it reviews nothing and prints the maintainer-takeover line; take that to the chief. Each run whose panel ran and exited 0 appends one `round-scope` row (`full` or `delta`, with its head and branch) to the CR ledger; a claude-only fallback appends none. Ready-check item 16b passes an outside PR only on a `full` row at its exact head.

   Every spent round increments one branch-scoped counter under the shared Git common directory, so a new commit or merge-forward does not buy a fresh three rounds and another branch starts independently. Carry forward the script's exact line: `pr-check: round N of 3 on <branch>` (with `(increment from <sha>)` on an increment round), `pr-check: delta round N on <branch> (from <sha>)` past the cap, or `pr-check: round N carried on <branch>`. Skip paths such as `CR_PROFILE=none` and an empty diff do not advance it. **Round 1 reviews the whole PR; every later round reviews only its increment.** `review-round.sh start` computes it from the reviewed head R (the head the last counted round ran on, `<branch>.head` beside the counter, never a ledger row the session could append, with a critic-panel `avail ok` row there): when a merge of the base is in `R..<head>`, the base's merged content is taken out, so the panel sees only the PR's own new lines and the conflict-resolution lines, with the whole PR as context. Its class decides the spend: a clean merge of the base into R is **carried** (no panel, no count; the marker carries the head); a tests-only increment, a comment-only one, one whose every line resolves a conflict, or a fix whose every non-test path is the file of a finding still open at the reviewed head (or at a head a free round followed) is a **free** round (at most 80 diff lines, five per PR, never counted); anything else is **work** and spends a round. **After round 3 a work increment runs only as ONE delta round:** when a critic-panel finding at R (never a `claude`, `claude-floor` or `codex-adv` row) still asks for a fix — its verdict after amends is agreed, fixed or unset, and it was never deferred or disproved — or when a chief judge recorded a NO-GO for that head with `chief-kit/write-verdict.sh` — one unconsumed record buys one round, and it buys the round only when its `pr:` line names the one open PR `gh pr list --head <branch>` resolves and any `branch:` line names this branch (no `pr:` line binds nothing, an unresolvable PR refuses, and an unbound NO-GO still counts toward the repeated-class stop below). Every round past the cap, free ones included, has the blocking set Critical or escape-class only — every other finding is deferred at step 4.9. A 4th FULL round (same head, `--full`, a head that does not descend from R, or no `--head`), a work increment with no trigger and a second delta round all exit 8 with the reason, review nothing and do not advance the counter: take that to the chief, never re-run to get past it; the refusal names the rethink first (split the PR or narrow the change), then the chief for a judge NO-GO or a grant. The round does **not** clear anything here: final adjudication still has to finish. The script-driven cap disposition runs only at step 4.9.

   **The increment is review-round.sh's, never re-derived here.** `panel-first-pass.sh` reviews `<L>..<head>` exactly as `start` printed it (`<round> increment <L>` or `<round> delta <L>`), with the whole PR (`<db_sha>...<head>`) as the critic's `<context>` (the critic raises a finding on code outside the increment only if the increment breaks it, and such a finding carries `[context]`); a bare `<round>` (round 1, `--full`, or no increment) reviews the whole PR. Its stderr says `round N reviews <L>..<head>`. A `--context-file` the caller passed stays as given. After the panel of every round below the cap but the first full review (an increment round, a free one at count 1 included, or a full review at count 2 or 3), `critic-pre-existing-tag.py --increment` runs `git blame` on the cited line of each Important finding: a line older than the PR gets the tag `[pre-existing]` and an amend row setting the ledger field `pre_existing` (step 4.5 says what that field does); a line the PR changed in an earlier round gets the informational `[outside-delta]`. Only a line the reviewed diff did not show is tagged: one inside any hunk of it, its context lines and the neighbours of a deletion included, is left alone, because the change may have broken it. A Critical, a Suggestion, a `[context]` finding, a citation that is not `file:line`, round 1 and every round past the cap are never tagged, and a tag the model wrote itself is stripped. Any failure leaves the findings untagged, and an untagged Important blocks.

   **Judge-triggered deltas stop on a repeated class.** A judge NO-GO at the last reviewed head can buy another delta, but every newly written NO-GO must carry one `class:` field: one value or a comma set from `option-parsing, cwd-indirection, shell-parsing, tool-defaults, reader-allowlist, other`. The branch identifies the PR; its consumed-qid history plus the candidate qid supplies earlier heads. An overlap with an earlier head's NO-GO classes refuses the delta (including `other`); another NO-GO at the same head is not a repeat, and legacy classless records contribute no classes. Do not relabel a repeated finding to buy a round: carry its earlier class into the delta brief and take the stop to the chief. The way out is a recorded `layer-decision: text|os|classifier|accept <reason>` line in the candidate evidence, not another spelling or another round. The line is read from a signed NO-GO at the last reviewed head and, as a second place, from a signed judge GO at the round head (the `--head` the delta runs on) that names this PR, sits in the qid holding the current NO-GO, and carries no `delta-scope:` or `delta-from:` line; a `delta: no-op` GO does not carry it, and a NO-GO for the round head in any qid (or a record that cannot be read whole) withholds it. **A same-uid file-access claim goes to the OS layer** via that layer decision, not another text-guard review round.

   **Read both streams; never merge them.** The script prints `captured diff base: <db> (<db_sha>)` and then the panel's merged findings block on **stdout**, and every status/skip note plus every `panel-availability:` line on **stderr** (step 4.5 records the availability rows from that stream). `<db_sha>` is the diff-base pin. **Its only remaining consumer is step 3.6**, which takes it as `<base>` in the `<base>..<head>` range of the impacted-suites commands; its former call site, step 3.2 phase B's `--base-sha`, was deleted with the CodeRabbit CLI. Read it, quote it in your report, carry it forward to step 3.6, and do not paste it into any other flag. Its purpose is now diagnostic: it is the base the panel actually reviewed against, which is what makes an exit-7 abort below legible. The pin itself is still load-bearing INSIDE `panel-first-pass.sh`, which captures the base once and hands the same value to the panel rather than re-resolving it live; the pin exists because two lanes minutes apart used to re-resolve independently, so a base branch that moved mid-run left them reviewing different ranges of the same head while the `--head` pin kept passing. One lane remains, but the capture stays — a base that moves between capture and review is still a range the ledger would misdescribe.

   The panel's Critical/Important findings are BLOCKING CANDIDATES, not blockers yet: they flow into step 3.2, where you adjudicate them and write the `VERDICT` lines step 4's cross-check and `orphan-check.sh` are structurally derived from. Nothing here writes the prior-blocking file — writing a raw candidate count BEFORE adjudication is exactly what let the round-3 hole through. The count now follows the verdicts, so it can only be >0 when a candidate actually SURVIVED adjudication.
   Why the script retries: when the environment token-proxies git (rtk), a plain `git diff <db_sha>...<head>` returns a stat summary, not a unified diff — `critic-panel.sh` rejects that as "no valid diff" and exits 1 (indistinguishable, by rc alone, from a genuine all-critics-failed panel). So the script re-fetches the diff through `rtk proxy git diff` and retries the panel ONCE before falling back to claude-only. (Both diffs use the CAPTURED base SHA, never the live base name.) The retry's output REPLACES (overwrites, not appends) the first attempt's findings and `panel-availability:` lines, so a stale first-attempt availability line can never leak into the aggregate; rc=1 after the retry still degrades to claude-only, loudly. Carry whatever lands on stdout into step 3.2 phase A.

   **Panel exit 7 = input-pin mismatch — ABORT, never degrade.** Every other panel failure fails OPEN to claude-only, because a missing reviewer is survivable. Exit 7 is not a reviewer failure: it means the checkout is no longer at the SHA step 0 captured, or the diff BASE no longer resolves to the commit step 3.0 captured (`db_sha`), so the diff, the review, and the ledger stamp would describe three different things — and the two review lanes, minutes apart, would not even share a base. There is nothing to degrade to — a claude-only fallback would review live state and record it against the captured head just the same. Stop the run, tell the operator, and re-run `/pr-check` from step 0 (which re-captures branch + HEAD, and step 3.0 the base SHA).

   **Panel exit 6 = certify refusal — claude-only, but the CR marker stays held.** The panel rejected blocking evidence and could not mint the citation-guard digest (`sha256sum`/`shasum` missing or failing), so it refuses to certify the run and emits no review body. It records an `avail ... unavailable reason=certify-refused` row on the ledger first, and `clear-review-marker.sh` then refuses that SHA (gate 2b) whatever another lane's `avail ok` says. `panel-first-pass.sh` degrades the review to claude-only with a `REFUSED` note, **not** "all critics failed" (exit 1); if the refusal row could not be recorded it aborts with exit 7 instead, since nothing would hold the marker. Fix the digest tooling and re-run `/pr-check` on a new HEAD; the hold is per SHA.

   The panel's `[<slug>-N]` Critical/Important findings are BLOCKING
   CANDIDATES under the adjudication rules below. Panel Suggestions are NOT
   forwarded to agents — append them directly to the aggregate
   `## Suggestions` section in step 3's output (step 7 files them).

   **End of the panel = a ci:go release event.** Once the panel's findings are in hand, run `bash "<himmel_dir>/scripts/lib/cr-first-release.sh" --pr <pr> --head <head> || true`. It reads the `CI_GO_GATE` switch first and prints nothing when it is off; when on, it releases `ci:go` at this head if the reviewer gate already passes, or prints why it holds. Best effort: a failure here never blocks the review.
