**Phase 4 — Dispatch decision (after the clip-body pivot: no external re-fetch).**

Pick ONE of two paths per clip:

| `type:` + URL pattern | Path | Skill |
|-----------------------|------|-------|
| `research` / `article` with any `github.com/*` URL except a `/blob/` file or a release-tag clip with notes (repo-root, `/tree/<branch>`, issues, pulls) | **github-ingest** | `obsidian-triage:luna-ingest` |
| a `github.com/<owner>/<repo>/releases/tag/<tag>` clip that carries text of its own (a feed clip carries the release notes; a body of only the link is not notes) | **clip-body** | none — the notes are the article: the repository is not ingested, the Phase 4.5 injection screen runs, and a short note is not a thin body |
| `research` / `article` with a `github.com/<owner>/<repo>/blob/<branch>/<path>` URL (one file is a distinct document from the repo root) | **clip-body** | none — luna-ingest keeps only owner/repo and would re-ingest the README, so the clip's own captured body is the harvest |
| every other case (tweet, youtube, reddit, newsletter, non-github research/article, unrecognised `type:`) | **clip-body** | none — clip body IS the harvest |

**github-ingest path:**
- Invoke: `Skill { skill: "obsidian-triage:luna-ingest", args: "<canonical-url> --vault <vault>" }`.
- Pass ONLY `--vault` (and `--dry-run` when the harvest pass is itself a dry-run), plus `--skill-scan` (the advisory SkillSpector step) when the clip's pre-canonical source `url:` is a `/tree/<branch>/<path>` whose path has a `skills` segment (Phase 3 canonicalization strips `/tree/`, so the canonical URL can never carry it); in that case pass the pre-canonical tree URL, not the canonical one, as the luna-ingest input so the requested branch and subtree survive: a clipped skill gets the advisory SkillSpector Stage 1 scan before it is used. The scan is local apart from its api.osv.dev CVE lookup of lockfile dependencies, advisory (a finding never changes `harvest_status`) and degrades to `skill_scan: unavailable` when SkillSpector is not installed. A `/blob/.../SKILL.md` clip stays on the clip-body path and is not scanned. NEVER pass `--research` — it is an interactive, web-search-costing enrichment the operator opts into per-run; the batch harvest dispatch must stay light and side-effect-bounded.
- On success: skill writes the synthesis to `30-Resources/Tech/<slug>.md`. The clip gets a `## Harvested content` section (per Phase 5) that wikilinks to that file.
- If skill returns rc=3 (target file exists): treat as success. `harvest_status: ok`, `harvest_dedup_target: [[30-Resources/Tech/<existing-slug>]]`, write the back-reference into the clip's `## Harvested content` instead of the full synthesis.
- Per-clip timeout: 5 minutes wall-time. On timeout: `harvest_status: failed`, `last_error: timeout_5min`.
- Skill error: `harvest_status: failed`, `last_error: <short>`.

**clip-body path:**
- No external skill dispatch. The clip's existing body (`## The Idea` / `## Summary` / `## Highlights` / etc., captured by the Web Clipper templates) IS the harvested content.
- **Thinness gate (mechanical — single source of truth, shared with vault-first link reading).** Before marking a clip `harvest_status: ok`, get a thinness verdict from the shared predicate — do NOT eyeball it. Shell out (mirrors how the Phase-4.5 injection screen shells out to `harvest-clip-body-batch.py`):

      node <plugin>/tools/is-thin-cli.mjs "<vault>/Clippings/<clip>.md"   # prints `thin` or `rich`

  `is-thin-cli.mjs` reads the clip, parses `type:` AND `source:`, and applies the `isThinClipBody` predicate in `tools/lib/clip-lookup.mjs`. Dispatch is **source-host first, then type** (host beats type): a reddit `source:` host (`reddit.com`/`old.reddit.com`/`redd.it`) routes to the reddit predicate regardless of `type:` (legacy browser-clipped reddit clips are `type: article`); otherwise per-type dispatch (tweet → `isThinTweetBody`; article/research → known content sections vs placeholder lines). Route on the verdict:
  - `rich` → proceed to the `harvest_status: ok` path below.
  - **Tool-deps preflight (the plugin cache ships no `node_modules`) — reached ONLY on the enrich rung below.** `tools/fxtwitter-enrich.mjs` imports `js-yaml`, which `tools/.gitignore` keeps out of git — so a plugin-cache install never has it and an enrich call would throw `Cannot find package 'js-yaml'` and revert its write. The FIRST time a clip in this run reaches the enrich rung, run `bash <plugin>/tools/ensure-deps.sh` **once** (subsequent clips skip it — already ensured this run); idempotent + fast when deps are present, installs them (browser-download-free) when absent, non-zero + a remediation message if it can't — treat that non-zero the same as any other env-unusable precondition (exit 2, per the exit-code table above). **Skip it entirely under `--dry-run`** (`DRY_RUN=1`): a dry run dispatches no enrich rung and `ensure-deps.sh` is not read-only (it may `npm install`), so running it would violate the `--dry-run` hard gate above. A batch with no `thin` X clip likewise never reaches here, so a github-only or already-rich batch never triggers a tool-dep install. (The tool's own exit-code-0-on-failure when js-yaml is missing is a separate, not-yet-fixed defect — this preflight prevents the missing-dep condition from occurring at all.)
  - `thin` + **X** clip (`x.com`/`twitter.com`) → enrich via `tools/fxtwitter-enrich.mjs` (browser-free, api.fxtwitter.com), then re-run the verdict.
  - `thin` + **reddit** clip (source host `reddit.com`/`old.reddit.com`/`redd.it`) → no enrich rung (the cookie-backed `reddit-enrich.mjs` was removed with every cookie media path); the batch tool's cookieless Scrapling `local-headless` thin-body ladder fetches it.
  - `thin` + **YouTube** clip (canonical `youtube.com/watch?v=<id>`, keyed on host NOT `type:`; e.g. a bare Telegram-clipped watch link) → the batch tool runs `tools/yt-scrapling-meta.py` under the scrapling venv python (`~/.himmel/scrapling-venv`, override `YT_SCRAPLING_PYTHON`) with NO cookie: title, channel and description from the watch page via Scrapling, transcript from yt-dlp json3 (Scrapling-first, no cookie workarounds). It writes a `## Harvested content` section and marks `harvest_skill: youtube-scrapling`, `harvest_status: ok` only when a transcript was captured (clips are captured in full, never silently partial: metadata without a transcript is not a harvest, so it takes the deferred thin-body partial below, its log line naming `transcript unavailable (<error>)`). The section is re-screened by the Phase 4.5 injection scanner. A miss (no venv, login wall, removed, timeout, the per-site scrape routing denying `local-headless`) falls through to the deferred thin-body partial below, its log line naming `youtube-scrapling: <reason>`, so a later run retries it. `--dry-run` reports the plan and never calls the helper.
  - `thin`/`failed` + **instagram** clip (`source:` host `instagram.com`, keyed on host NOT `type:`) → do NOT auto-download media (the heavyweight `/ig-media-enrich` rung is lean-invoke). Mark `harvest_status: partial` + the dedicated boolean key `ig_media_pending: true` so `/ig-media-enrich` finds the batch. This is a **deferred** partial (see "Partial classes"): it does not block `.harvest.done`. This is deliberately NOT a `harvest_flag` value (`harvest_flag` is single-valued and `/triage-clips` keys its untrusted-content handling off `harvest_flag: injection-suspect` — overloading it would clobber an injection flag). The media rung clears `ig_media_pending` when it completes the clip. The `ig_media_pending` write is a frontmatter-only mark (same G-3 body-identity discipline as the other harvest marks).
  - `thin` + **article/web** clip (the G-1 privacy gate passing) → the thin-body fetch below, run by the batch tool on every run with no flag, then re-run the verdict.
  - `thin` + **article/web** clip the fetch did not fill (every free rung failed, the page held no text, the per-run cap was reached, or the host is outside the fetch routes) → do NOT mark `ok`. Log `~ <clip> — partial (thin-body): clipper captured only a skeleton; enrichment needs fxtwitter/firecrawl`. Set frontmatter `harvest_status: partial` + `harvest_flag: thin-body`; state-file `harvest_status: partial`, `harvest_skill: clip-body`, `last_error: thin_body`. Skip the body write in Phase 5; only do the frontmatter mark. (The honest mark for e.g. a `docs.github.com` clip whose Web-Clipper template captured only placeholders — strictly better than the old `ok`-with-empty-body.)
  - **A summary triage wrote from the URL is not page text.** A `## Summary` section carrying `Inferred from the source URL only` is triage's guess (`summary_basis: url-only`); both thinness tests (`is_thin_body` in the batch tool, `isThinClipBody` in `tools/lib/clip-lookup.mjs`) leave it out, so a clip whose only text is that summary reads `thin` and can never be stamped `ok` over it. An Instagram clip is judged by its own media rule instead: captured when `## Crawled content` holds a `### Transcript` or `### Slides` subsection.
  - `thin` + **repo** clip (`github.com`) → dispatch `obsidian-triage:luna-ingest` (the Phase-4 github path already owns this).
  - **Enricher-gap flag (an inventory of enrichers still to build).** When a thin clip's canonical host matches none of the dedicated enricher routes above AND is a KNOWN PLATFORM host that needs one (curated `ENRICHER_GAP_HOSTS` in `tools/harvest-clip-body-batch.py` — tiktok, linkedin, bsky, threads, facebook, pinterest, twitch, spotify, mastodon, `*.substack.com`), the batch tool ALSO writes `harvest_enricher_gap: <host>` alongside the thin-body marks (frontmatter-only, G-3 body-identity, idempotent). It does NOT fire for generic article hosts (those the clip-body/firecrawl path handles) — so the flag distinguishes "genuinely missing a dedicated enricher" from a plain skeleton article. `/archive-clips` Phase 5 rolls these up into a `## Enricher gaps` section in `_deferred.md` (by host, count desc) = the backlog of enrichers still to build. It is a distinct key, NOT a `harvest_flag` value (which owns injection semantics).
- **Thin-body fetch (the default) and the paid escalation (opt-in).** A thin clip whose canonical URL is a genuine **article/web** URL (NOT `x.com`/`twitter.com` → fxtwitter owns X; NOT `github.com` → luna-ingest; NOT `youtube.com`/`youtu.be` → youtube-scrapling; NOT `instagram.com` → ig-media-fetch (the Instagram media rung)) is fetched by `harvest-clip-body-batch.py` on **every run, with no flag and no key**, through the free rungs of the scrape chain in their configured order (`local-headless`, then `jina`; a rung that is not installed is skipped). The markdown is written as a `## Harvested content` section before `## Source`, marking `harvest_skill: <the rung that served it>`, `harvest_status: ok`, and dropping the stale `harvest_flag: thin-body`. Bounds: `--fetch-budget N` / `HARVEST_FETCH_BUDGET` (default 20) caps fetch **attempts** per run — failed ones count, so a night of failures stops at the cap — and each rung keeps its own timeout (Jina 45 s, local headless 60 s). A fetch that fails, returns a page with no text at all, or is cut off by the cap leaves the clip a **retryable partial** (no `harvested_at` written): a failed or empty fetch bumps `harvest_defer_count` and writes the same frontmatter marks as an unfetched skeleton (injection flag, enricher gap); a cap cut-off bumps nothing. Private/internal URLs and the vault's `.harvest-deny` list are never fetched — the **G-1 privacy gate** applies to this egress path. The fetched markdown is untrusted web text → it is re-run through the Phase 4.5 injection screen, and `harvest_flag` is set on a hit. `--firecrawl-thin` adds the **paid** firecrawl rung after the free ones (credit-conscious: the free tier is 1000 credits/mo, ~1 per scrape; `--firecrawl-budget N`, default 20, caps its calls; needs `FIRECRAWL_API_KEY`, optionally `FIRECRAWL_BASE_URL`). Without the flag firecrawl is never touched. `HARVEST_SCRAPE_DENY=all` turns every fetch off; a thin clip then stays `partial` as above.
- **A partial is retried where it sits.** `/triage-clips` moves a processed clip to `_evidence/`, which the inbox scan skips. The batch tool therefore also visits `_evidence/` clips that are still `harvest_status: partial` (never `_rejected/`, never `harvest_needs_attention: true`) whose host it can fetch (article/web, or a YouTube watch link), after the inbox clips and under the same fetch bounds and the same defer count (needs-attention at 5, then logged in `.harvest-pending.md` and left). An X or Instagram partial there waits for its own enricher and is only listed in the pending report. The clip is filled in place and never moved back.
- Else: log `✓ <clip> — harvested via clip-body, {Nb}b content (clip-body, no fetch), harvest_status=ok` (per G-7 logging contract — `{Nb}` is the body byte count). Phase 5 skips the body write entirely (no `## Harvested content` section needed — body already is the harvest); only the frontmatter `harvested_at:` + `harvest_skill: clip-body` markers are added.

**No-headless contract (the no-headless-claude rule):** all dispatch happens via `Skill` tool ONLY. NEVER `Bash: claude -p` / `--print` / `--bg`. NEVER any Anthropic API direct call. The clip-body path makes no external calls at all (no API keys needed); the github-ingest path uses `gh api` via luna-ingest.
