## Verification and re-sync

The dependency boundary is deliberate: the vendored runtime runs trusted local
TLA+ specs and optional trusted JS views, spawns Java, and writes staged output
only to a new/empty output directory. The upstream worker/janitor process-group
cleanup remains unchanged. Hermes `skills_guard` v10 (`source=community`) scans
the three added skills: both formal skills are safe; statechart is caution
(33 medium hits and one high). The high hit is the zero-width joiner in the
woman-technologist emoji test fixture (`scripts/test/labels.ts:163`), verified
as test data rather than an instruction. No critical hits were reported. Do not execute a model or view obtained from an
untrusted archive. Provision dependencies and run TLC on a test VM, not on the
station. The station prerequisite tests import the runtime without installing
or invoking Java; HIMMEL-6690 has explicit operator approval for that execution.

TLC 1.7.4 SHA-256 (same pin as upstream):
`936a262061c914694dfd669a543be24573c45d5aa0ff20a8b96b23d01e050e88`.
Node 22.18–22.x or 23.6+, Bun 1.1.5+, or Deno 2+ runs the TypeScript entry point.
`fast-check` 4.5.3 is an upstream test-only dependency, not installed by vendoring.
The manifest-coverage gate excludes only `skills/statechart/scripts/` from
Dependabot ownership, following the pinned claude-hud precedent: this upstream
manifest changes only with a reviewed re-vendor, not an independent bot bump.
The adjacent non-vendored package negative control remains subject to coverage;
production npm audit and the complete hash inventory still apply.

The upstream CLI replay tests use the same absolute, hash-verified TLA2TOOLS jar
prerequisite; without it, replay cases report an explicit skip instead of
failing before their fake Java wrapper starts. Launcher runtime-discovery cases
still run without a jar. CI checks both absent and invalid-jar skips and proves
no replay process starts. The valid-jar replay corpus has not been run for this
adaptation; a skip is not evidence that the replay corpus passes.
