The trail

Two parts. First, a practice climb: you install himmel on a spare project, see what it does, and remove it again. Then the levels: each one adds a part of himmel, says what it costs, and says how to turn it off. You need a Claude account to sign in to Claude Code. What himmel changes on your machine, and how to undo it: Start here. Words you have not met before: Questions and words.

Your first steps: a practice climb

Ten steps on a spare project you can delete afterwards. You install himmel, watch a guardrail stop a risky move, keep the install, make one change in its own worktree, and then remove everything again. Each output below comes from one real run on a clean machine; paths and commit hashes that differ on yours are shortened to "…".

$ you type it in your terminal› you type it to Claudedashed box: what you see✓ what success looks like

  1. Install the tools

    git, node with npm, jq, python3 and Claude Code. The installer stops and tells you if git, bash, jq, python3 or npm/bun is missing.

    Run · Debian or Ubuntu, needs sudo
    $ sudo apt-get update
$ sudo apt-get install -y nodejs npm git jq python3
$ curl -fsSL https://claude.ai/install.sh | bash

    Ubuntu's nodejs package ships without npm, hence the separate name.

    Run · with Homebrew
    $ brew install node git jq python bash uv
$ curl -fsSL https://claude.ai/install.sh | bash
$ uv tool install pre-commit

    The bash and python3 that macOS ships are too old for some himmel scripts.

    Success: if claude is not found, open a new terminal and it will be.

  2. Sign in to Claude Code

    Run claude, finish the sign-in in the browser it opens, leave with /exit. An account problem then shows up before himmel is involved.

    Run
    $ claude --version
    Real output
    2.1.305 (Claude Code)

    Success: a version number followed by (Claude Code).

  3. Make a spare project

    One empty commit on main. No remote is needed: without one, himmel cuts worktrees from your local main.

    Run
    $ mkdir ~/himmel-trial
$ cd ~/himmel-trial
$ git init -b main
$ git commit --allow-empty -m "chore: initial commit"
    Real output, at the end
    [main (root-commit) 02c1d2c] chore: initial commit

    Success: one empty commit on main, made before any himmel hook exists.

  4. Download himmel next to your projects

    Run
    $ git clone https://github.com/yotamleo-org/Himmel ~/himmel
    Expected
    Cloning into '/home/you/himmel'...

    Success: git ends without an error.

  5. Preview the install

    This writes nothing. It lists every file, setting and plugin the install would touch, then a summary. With --scope project the installer asks no questions; it uses the starter answers (install profiles lists the questions a bare install asks). Inside the script the starter set is called "core".

    Run from the project
    $ cd ~/himmel-trial
$ node ~/himmel/scripts/himmelctl/bin.js install --scope project --dry-run
    Real output, abridged
    ==> himmel adopter preflight (check-only)
WARN: scripts/jira/node_modules and scripts/jira/dist/index.js not built …
preflight OK
…
would install (--dry-run — NOTHING below was executed):
  + himmel (profile=starter, scope=project) — would run bash …/adopt.sh --profile core --scope project
  + workspace trust — would run ensure-workspace-trust.sh for the install target
…
next: commit these files on a branch

    The Jira warning is harmless on a starter install: the Jira command line is only needed if you track work in Jira.

    Success: the summary says NOTHING below was executed, and git status still shows a clean tree. In a real project, a would replace … line names each of your files the install would back up and replace.

  6. Install

    Before you press Enter

    • git status is clean. A same-named file in scripts/ is backed up before it is replaced, and left alone if the backup fails; a clean tree also shows you exactly what changed.
    • You accept that your project statusLine is replaced; the old one is backed up.
    • You know that from now on commits and pushes to main are refused, and a commit message needs a type such as feat: and a ticket reference such as #1.
    Run
    $ node ~/himmel/scripts/himmelctl/bin.js install --scope project
    Real output, the lines that matter
      .gitignore: added .claude/worktrees/
  The install is uncommitted on main, which the git gates now refuse commits on.
  Commit it once with: bash …/adopt.sh --scope project --target …/himmel-trial --commit-install
…
installed:
  + himmel (profile=starter, scope=project) via bash …/adopt.sh --profile core --scope project
  + workspace trusted: …/himmel-trial (hasTrustDialogAccepted written to ~/.claude.json)

    If your terminal asks Commit the install on main now (the one allowed commit there)? [y/N], answer y and step 8 is already done. Otherwise the installer prints the command for step 8, as above, with the full path to your himmel clone, so it runs from your project as printed.

    Success: both + lines are present. A note that ~/.local/bin is not on your PATH is normal; add the line it prints.

  7. Watch a guardrail refuse

    Start claude in the project and ask it to create hello.txt. The edit is refused because you are on the main branch.

    Type to Claude
    › Create hello.txt with the word hi in it.
    Real output, first lines
    ⛔ block-edit-on-main: refusing to edit `~/himmel-trial/hello.txt` — its repo is on main/master.
…
    bash scripts/worktree.sh feat/<scope>   # create the worktree

    The refusal names the command that fixes it, and that command is in your project now. Leave Claude with /exit. git refuses a commit on main the same way:

    Run
    $ git commit --allow-empty -m "chore: try main #1"
    Real output
    ERROR: Committing directly on 'main' is not allowed.

    Success: the refusal appears and hello.txt does not exist.

  8. Keep the install

    The install's files are still uncommitted, and main now refuses commits. The installer may make one commit there, and only for its own files:

    Run from ~/himmel-trial
    $ bash ~/himmel/scripts/adopt.sh --scope project --target ~/himmel-trial --commit-install
    Real output, at the end
      committed the install on main (chore: add himmel)
──── Done ────

    The install also added .claude/worktrees/ to .gitignore, so a later git add -A never stages a worktree. On a real project with a shared main, you can instead commit the install on a branch and merge it by pull request.

    Success: git log --oneline -1 shows chore: add himmel, and git status is clean.

  9. Work in a worktree

    A worktree is a second folder on its own branch. It is cut from main, which now carries himmel's files, so the guardrails come with you.

    Run from ~/himmel-trial
    $ bash scripts/worktree.sh feat/try-himmel
    Real output
    WARN new-worktree: uniqueness-vs-merged-PR check skipped (forge unreachable)
WARN new-worktree: no 'origin' remote - branching from local 'main'
OK new-worktree: feat/try-himmel → …/himmel-trial/.claude/worktrees/feat+try-himmel (log: …)

    Both warnings are normal for a project with no remote. Start claude inside the printed path and ask for hello.txt again; Claude Code asks your permission, as it always does for an edit. Then commit it. The commit rule wants a ticket reference:

    Run inside the worktree
    $ git add hello.txt
$ git commit -m "feat: add hello"
$ git commit -m "feat: add hello #1"
$ git log --oneline -1
    Real output
    COMMIT REJECTED: no ticket reference matched: (^|[^0-9A-Za-z_])(#|LOCAL-)[0-9]+([^0-9A-Za-z_]|$)
…
66493de feat: add hello #1

    Success: the second commit goes through, and ls scripts/hooks in the worktree lists himmel's hooks, so the guardrails came with you.

  10. Check, then undo whenever you like

    Run from ~/himmel-trial
    $ node ~/himmel/scripts/himmelctl/bin.js status
$ node ~/himmel/scripts/himmelctl/bin.js uninstall --dry-run
    Real output, abridged
    green  pre-commit-hooks  installed hook type(s): pre-commit, commit-msg, pre-push (…/.git/hooks)
green  wiring-pretooluse  …/himmel-trial/.claude/settings.json; …
…
0 red, 0 degraded, 7 green, 42 n/a (4 of them desired but not set up: see the n/a rows above)
…
DRY: Reconcile report - ledger …, 96 units
  reverted   82  (removed 82, restored 0, already-base 0, surgical 0)
  NEEDS YOU   0

    To remove it for real, run the same command with --yes instead of --dry-run, then delete ~/himmel-trial.

    Success: 0 red in the status count, and the undo preview has nothing that needs you. A green row means "found", not "working"; the n/a rows are features a starter install does not turn on.

"…" marks a path or text that depends on your machine. Full reference: Install on your project and Getting started.
