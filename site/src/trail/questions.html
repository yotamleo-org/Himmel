Questions and words

The questions people ask before they install himmel, then every word the trail uses that you may not know. What himmel is, what it installs and how to undo it are on Start here.

I have never used Claude Code. What is it?

Claude Code is Anthropic's coding assistant. You start it with claude in a terminal, inside a project; it reads the code, edits files and runs commands, and asks your permission before it does. It needs a Claude account. himmel works only on top of it, so install Claude Code and sign in first: steps 1 and 2 of the practice climb do both.

Who is in control?

  • You choose the starting point. A starter install for one project, or more: a second brain, a second reviewer, a fleet. Install profiles
  • You see the plan first. The installer lists everything it would add or change, and asks before it writes a thing.
  • Nothing runs on a schedule until you arm it, one job at a time.
  • Every guardrail has an off switch for one session, when you mean it.
  • One command takes it all back out. How

Does it change Claude Code in my other projects?

Not with the trail's install. --scope project wires only the project you install into. --scope user wires your own Claude Code settings, so it applies in every project. Two things are machine-wide either way: the himmelctl command in ~/.local/bin, and any setting in ~/.himmel/himmel.conf, such as the switch that turns off the ticket-reference rule.

Does anything run while I am not watching?

Not until you start it. A scheduled job runs only once you arm it, and disarm stops it again. A shift while you are away starts only when you type /afk-shift, and /stop ends it. The guardrails apply to every session, the unattended ones too.

What does it cost?

himmel is open source. The work it runs uses your Claude plan's usage, like any Claude Code session; heavy work checks how much you have left before it starts (Level 5). A second reviewer from another model family uses that provider's subscription (Level 4).

Which systems does it run on?

Linux and macOS. Where the steps differ, such as installing the tools, the trail shows a Linux and a macOS block.

A guardrail stopped me. How do I get past it?

The refusal names the command that fixes it. Most often that is a worktree, so the change happens off your main branch:

bash scripts/worktree.sh feat/my-change

When you mean it, turn one guardrail off for one session by starting Claude Code with its switch, for example:

EDIT_ON_MAIN_OK=1 claude

What keeps a long project fast?

  • Guards aimed at real damage. Each guard targets a move that can hurt a project, and is replayed against real commands before it ships, so it stops what matters and lets the rest through.
  • Long tracks keep their pace. Each session keeps its context small, so its answers stay sharp. When it fills, a worker hands off at a set point and the chief passes the shift to a successor, with everything written down, so a long track never starts over.
  • Every merge is earned. A change merges through one gate only: CI green at its exact commit, every review point decided, and an approval signed for that commit.
  • Cleanup keeps every session fast. Stale worktrees and open tickets slow down each session that has to step around them, so finished worktrees are cleared and tickets close when their change merges.

Words you will meet

In the order a newcomer usually meets them. Every other term is in the full glossary.

Worktree
A second working folder of the same git repository, on its own branch. himmel makes every change in one, so your main branch stays as it is until the change is merged.
Hook
A small script that runs by itself when something happens: before Claude Code edits a file or runs a command, or before git makes a commit or a push. A hook can refuse the action. himmel's guardrails are hooks.
Gate
A check that must pass before work moves on: before a commit, a push or a merge. A git hook is the most common gate.
CR (code review)
The review a change gets before it merges. /pr-check runs it: reviewer models read the change, and each point they raise is fixed or answered before the merge.
Panel
The reviewers that read one change together. The starter panel is Claude; adding a second model family at Level 4 widens it.
Critic
One reviewer model on the panel.
Attestation
A line in a commit message that records what was checked, for example Platforms tested: linux. A project that requires one refuses a push without it.
Handover
A short written note a session leaves so the next one can pick up where it stopped. A Claude Code session forgets everything when it ends; the note does not.
Vault
A folder of markdown notes, the kind Obsidian opens. himmel can fill it, link it and search it: your second brain, Level 2.
Cadence
A job that runs on a schedule, such as re-indexing your notes every night. None runs until you arm it.
Lane
Where a piece of AI work runs: on Claude, or on another provider's model such as OpenAI's Codex. The installer's lanes question sets up the extra ones.
Chief
One long-running Claude session that keeps several tickets moving at once: it starts the workers, answers their questions and approves each merge.
Worker
One ticket, one worktree, one pull request: a session the chief starts, which reports back to it.
