himmel · for Claude Code

Ship more with Claude Code, and keep every change reviewable.

What himmel is

Claude Code is Anthropic's coding assistant: it reads your code, edits files and runs commands from your terminal. himmel adds a fixed way of working to it: every change is made on its own branch, checked and reviewed, and only then merged into your main branch. Small scripts enforce that by refusing the risky moves, so the rules hold even when nobody remembers them.

Who it is for: developers on Linux or macOS who use git and a terminal.

What it installs, and where

Into the project you pick: helper scripts in scripts/, settings in .claude/settings.json and git hooks in .git/hooks. In your home folder: a himmelctl command, a cache and a trust entry for the project. It lists everything before it writes, and backs up each file it replaces. The full list

How to undo it

From the project you installed into, with himmel cloned to ~/himmel:

node ~/himmel/scripts/himmelctl/bin.js uninstall --yes

It removes what the install added and restores what it replaced. Run it with --dry-run in place of --yes to see the list first.

What changes on your machine

Everything below is recorded at install time, and the undo above takes it back out.

Read these four first

  1. Helper scripts are copied into scripts/. A file with the same name is replaced only after himmel has backed it up, and uninstall restores it. If the backup cannot be made, the file is left alone and the install says not replaced … (cannot back up the existing file; left untouched). The preview lists every file it would replace.
  2. Your statusLine is replaced in .claude/settings.json, and ~/.claude/plugins/claude-hud/config.json is rewritten. Both old values are backed up and uninstall restores them.
  3. Commits and pushes to main are refused at once. If your project has no .pre-commit-config.yaml, the install places himmel's own git gates. They refuse a commit on main, a direct push to main, and a commit message without a conventional type and a ticket reference such as #1. No tracker? Answer none to the installer's tracker question, or put TICKET_ID_REQUIRED=0 in ~/.himmel/himmel.conf; that file applies to every project on this machine.
  4. The install itself starts uncommitted. Main now refuses commits, so the installer offers to make the one allowed commit there (chore: add himmel), or prints the command that does. Until the install is committed, a new worktree has none of himmel's files, so Claude runs there without its hooks.

In the project folder

  • Three hook entries, a status line and HIMMEL_REPO in .claude/settings.json.
  • Three git hooks in .git/hooks. Existing ones are saved as <hook>.himmel-backup and still run after himmel's.
  • Claude Code plugins, recorded in .claude/settings.json; the preview names each one.

In your home folder

  • A himmelctl launcher in ~/.local/bin, a cache in ~/.claude/himmel.
  • A trust entry for the project in ~/.claude.json.

Only if bun is installed

  • The qmd search tool, about 2.1 GB of search models, and an index of your himmel clone.

Left alone

Your notes vault, scheduled jobs, the Telegram bridge and the second-model reviewers.

Every part the installer can add is one item of the install manifest, {{MANIFEST_N}} items in all, {{CORE_N}} of them in the starter install, and himmelctl status checks each one. The full reference: Install on your project.

Anything the undo cannot reverse by itself, it lists under NEEDS YOU.
