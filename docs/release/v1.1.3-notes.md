# v1.1.3 release notes

**Release date:** to be set at tagging.

## What you can now do

- Keep the config UI running: `himmelctl ui --service install` sets up a
  background service on a fixed local port with a stable bookmark
  (`--service url`). The run page has a live board, a "Now" panel, folded
  finished subagent blocks, and names sessions from their branch or first prompt.
- See the context window size and effort level in the `claude-hud` status line.
- Turn on a repo map at the start of each worker with `LEG_REPO_MAP=1`
  (off by default; `LEG_REPO_MAP_TOKENS` sets the size).
- Ask `graphify` why/how questions and get the documentation and rationale
  nodes first.
- Let `obsidian-triage` follow-web search through DeepSeek as an opt-in step
  (`FOLLOW_WEB_DEEPSEEK=1` plus `DEEPSEEK_API_KEY`); vaults marked as salus
  are never sent.
- Use `qmd` query expansion on OpenRouter for non-salus collections.
- Use the new skills: `ticket-standard` (checks a ticket draft for Plan, DoD
  and named proof), an `adversarial-verify` that sorts findings into four
  buckets, and a `minerva` design step that grafts the best parts of several
  candidates.
- End-session can route learnings into skill edits (optional step).
- Template the overnight morning report to your own layout.
- `drift` reports upstream lag for fork defaults and pinned branches.

## What changed that you will notice

- **Jira Sector is opt-in.** `jira create` requires and sends a Sector only
  when `jira.sectorField` is set in `~/.himmel/config.json` (or
  `JIRA_SECTOR_FIELD`); unset sends none. Before this, `jira create` broke on
  every install that had no such field.
- `jira create` refuses a Task, Story or Bug without Plan and DoD sections,
  and without an epic or standalone marker.
- Telegram `/stop` and the other control verbs act only for the operator.
- `qmd embed` and graphify refresh now run every two hours.
- `himmel doctor` checks more: hook events at the right indent, a missing cron
  entrypoint, an unfenced hermes cron worker, and a fail-open guard.
- Merging a ticket's PR with a bare merge reports the ticket status unchanged
  instead of claiming a Done transition.
- Uninstall restores an explicit null `env` or `hooks` container and a
  previous lane allowlist after an interrupted install.

## What you must do on update

- Run your usual `himmel update`.
- If you use Jira Sectors, add `{"jira": {"sectorField": "<customfield id>"}}`
  to `~/.himmel/config.json`, or run `jira sector setup` to create the field
  and print that snippet. If you do not, nothing to do.
- To keep the config UI up across logins, run
  `himmelctl ui --service install` once.

## Known issues

- Carried from v1.1.2: claudex auto mode does not block destructive actions;
  run no unattended claudex workers.
- Carried from v1.1.2: the guard set has known gaps (git global options that
  hide `push --force`, several destructive verbs outside `rm`); the `guards`
  label tracks them.
- `himmel-bus` is opt-in until its station acceptance closes.
- Windows remains unsupported.
