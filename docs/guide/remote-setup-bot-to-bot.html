himmel guide · remote setup part 4

Two stations, one Telegram group

This page sets up bot-to-bot: two himmel stations that talk to each other through one Telegram group. The stations can be yours and another person's, or two machines of your own. You need no shared network, no SSH and no shared folder: everything goes through Telegram. It takes about 15 minutes.

What you will have at the end

  • Each station has its own bridge bot, and the two bridge bots share one private Telegram group.
  • A small program on each station, the poller, keeps the connection going.
  • Your setup command ends in one line that starts with DONE:.
  • Your main bot (part 1) stays private, outside the group, exactly as it is now.

Four steps

  1. Make a bridge botEach station, in Telegram with @BotFather.
  2. Make the groupThe group owner only, once, in Telegram.
  3. Run one commandEach station, in its own Terminal.
  4. CheckEach station: one command that only reads.

Before you start

You need:

  • Part 1 done: your main bot works. If not, do part 1 first (about 5 minutes).
  • The Telegram app on your phone, signed in.
  • A Terminal window of your own: a separate window, not Claude and not a ! command inside Claude. The helper handles secrets and refuses to run there.

In that Terminal window, go to your himmel folder. This page assumes it is ~/himmel:

cd ~/himmel

If you cloned himmel somewhere else, type cd and a space, drag that folder from your file manager into the Terminal window, and press Enter. Every command on this page runs from that folder, and works unchanged in bash, zsh and fish.

The traps, up front

  • Your main bot never joins the group. Only the two bridge bots go in. The bridge bot is a new, second bot.
  • Flip the group to Public, then back to Private. That turns it into a supergroup, which bridge bots need.
  • Turn off "Change group info" and "Pin messages" for members.
  • Bridge bots are administrators with every right switched off.
  • Add bots by their username. Invite links do not work for bots.
  • Never post anonymously "as the group". The bridge ignores those messages.
  • Run the helper in a plain Terminal, not inside Claude. It refuses to run inside Claude.
  • On a Mac: turn on "Prevent automatic sleeping when the display is off" (System Settings → Battery, or Energy). A sleeping Mac stops the poller, and Telegram keeps the messages for only 24 hours.

Which station are you? Pick one to see only your steps.

1. Make your bridge bot

each station

1.1Make a new bot with @BotFather

In Telegram, open a chat with @BotFather (the official bot with a blue check mark) and send this. Give the bot any name, and a username that ends in bot. This is a new bot, not your main bot. If both stations are yours, make two bridge bots, one per machine.

send to @BotFather
/newbot
You should see

A reply with a line that starts with "Use this token to access the HTTP API". The token is the long line below it. Keep this chat open: you paste the token in step 3.

If not

If the helper later says this bot is already your ... bot, you used a bot you already have. Each role needs its own bot: send /newbot again.

1.2Turn on Bot-to-Bot mode

Send this to @BotFather, pick the new bot, open Bot Settings and turn Bot-to-Bot mode on. Leave Group Privacy on (it is on by default).

send to @BotFather
/mybots
You should see

Bot-to-Bot mode shown as on, and Group Privacy still on.

If not

Check you picked the new bridge bot in the list, not your main bot.

1.3Send your bridge bot's username to the other operator

Send the other station's operator the username of your bridge bot (the one that ends in bot). The group owner needs it to add your bot. On two machines of your own, just note both usernames.

You should see

Each side knows the other side's bridge bot username.

If not

If the helper later says not a usable Telegram username, ask the other operator to check their bridge bot's username, then run the command again.

2. Make the group

group owner only, once

The group owner does this part. Wait until they tell you the group is ready, then go on to step 3. If the helper later names a group setting, ask the group owner to change it.

Do these in this order. The order matters.

2.1Make the group

Press New Group. Add only your own bridge bot, or, if another person runs the other station, only that person. Name the group anything.

You should see

A new group with you and that one member.

If not

If Telegram will not let you add the bot, check its username with step 1.3.

2.2Flip it Public, then Private

Open the group, press its name, then Edit → Group type → Public → set any link → Save. Then Edit → Group type → Private → Save. This turns it into a supergroup.

You should see

The group type is Private again. The helper checks the supergroup part in step 3.

If not

The helper says and bridge bots need a supergroup: do this step again.

2.3Turn off two member permissions

Edit → Permissions → turn off Change group info and Pin messages.

You should see

Both switches off.

If not

The helper says group members are allowed to use: turn both off again.

2.4Add the other bridge bot by username

Press Add Members and add the other station's bridge bot by its username. If another person runs it and you did not add your own bridge bot in 2.1, add that one too. Invite links do not work for bots.

You should see

Both bridge bots in the member list. Your main bot is not there.

If not

The helper says is not in the group: press Add Members and add the bot by its username. It says your main bot is in the group: remove your main bot; only the bridge bots belong in it.

2.5Make each bridge bot an administrator with every right off

Edit → Administrators → pick each bridge bot (press Add Admin first if it is not listed) → switch every right off → Save.

You should see

Both bridge bots listed as administrators.

If not

is not an administrator of the group: Edit → Administrators → Add Admin → pick the bot, switch every right off, Save. has the admin right: open that bot there and switch that right off, then Save. If the line names a raw field such as can_manage_tags, switch off the toggle with the matching name.

2.6Say hello in the group

Send this word in the group yourself:

send in the group
hello
You should see

Your message in the group, posted under your own name.

If not

It shows the group's name instead of yours: see 2.7.

2.7Never post "as the group"

Leave off the switch that makes an administrator anonymous. The bridge ignores messages posted "as the group".

You should see

Every message in the group shows the name of the person or bot who sent it.

If not

The helper says is not set up as a plain administrator: open Edit → Administrators → the bot, switch every right and "Remain anonymous" off, and Save.

3. Run one command

each station

3.1Run the helper in your Terminal

In your own Terminal (not Claude), from your himmel folder:

bash scripts/remote-setup/remote-setup.sh peer

On the first run it asks for your bridge bot's token: paste it and press Enter. Nothing shows on screen while you paste: that is on purpose. On every later run, just press Enter at that prompt. You type no bot id, no username and no chat id: the helper finds them.

You should see

Steps marked ok, then it looks for your group.

If not

do part 1 first: finish part 1, then run the command again. this step handles secrets and must run in a separate plain Terminal: open a Terminal window of your own, not Claude, and run it there.

3.2Send hello when it asks

If it asks you to send the word hello in the group ("Waiting up to 10 minutes..."), send it now. A hello sent before the command started is not seen.

send in the group
hello
You should see

It finds your group and posts one short line, himmel peer hello, in it. Then it waits up to 10 minutes for the other station's bridge bot to do the same.

If not

no hello arrived from the group: run the command again, wait until it asks, then send hello. no hello came from the other station: ask the other operator to run the same command once, then run it here again.

3.3Confirm the other bot: type 1 only if the name matches

When the other bridge bot says hello, the helper shows its @username and asks one question. Check the name with the other operator. Type 1 if it is their bridge bot, 2 if it is not. Nothing is paired unless you type 1.

type in the Terminal when asked, only if the name matches
1
You should see

It checks the group, adds and confirms the other station, and starts the poller. The last line:

DONE: peer goomal — group confirmed, poller running

The name after peer is the other station's name, taken from its bridge bot's username (here goomal_bot). Running the command again is safe: it changes no setting, and posts the hello once.

If not

so nothing was paired: ask the other operator for the name of their bridge bot, make sure only that bot is in the group, then run the command again and type 1 only if the name matches. Any other FIX: line: see the full table below.

Timing

  • One person, two machines: start the command on the first machine. While it shows "Waiting for the other station's hello", run the same command on the second machine. If the first machine gave up meanwhile, run the command there once more: nothing breaks.
  • The other station finished before you: your run still ends in DONE:. Ask the other operator to run the same command once. It changes no setting on their side, and it makes their station post its hello for you to find.
  • On a Mac: the poller is a LaunchAgent (com.himmel.peer-bridge). Turn on "Prevent automatic sleeping when the display is off" in System Settings → Battery (or Energy), or the poller stops when the Mac sleeps.

4. Check everything

each station

4.1Run the status check

This command only reads: it is safe at any time and changes nothing.

bash scripts/remote-setup/remote-setup.sh status
You should see
DONE: status — all shipped parts ok
If not

The last line is a FIX: that names the part and its command. Run that command.

Why doesn't it answer me?

The group is for the two bridge bots, not for people. The bridge ignores:

  • every message from a person, including you, the operator;
  • every message that does not start by addressing your bridge bot;
  • messages posted anonymously "as the group".

It drops them silently: nothing in the group tells you it did. That is on purpose, not a fault.

To talk to your own station, use your main bot (part 1) in its private chat, not the group.

Swapped a bot or account?

You replaced your bridge bot

Run this on your station, and paste the new bridge bot's token when it asks:

bash scripts/remote-setup/remote-setup.sh peer --replace

The other station changed its bridge bot

Both sides run the same command, so each finds the other again:

bash scripts/remote-setup/remote-setup.sh peer --replace

You switched your Claude account

Nothing to do. The bridge does not use your Claude account: the poller never calls Claude.

You swapped your main bot, your Telegram account, or made a new group

Not automatic yet. A fix is tracked; until it lands, ask your chief. There is no command for these today.

Undo

To remove a peer, stop its poller and delete the poller's unit when it was the last one:

bash scripts/remote-setup/remote-setup.sh peer --remove

It asks you to type yes before it removes the peer. If the command is interrupted half way, run it again: it finishes the job. To delete the bridge bot itself, send /deletebot to @BotFather; to leave the group, remove the bot there.

Optional: chief-to-chief jobs

Not needed for DONE:. Your chiefs can exchange signed job requests once each operator has trusted the other's key, read out by voice or another messenger. There is no helper for that: see the peer bridge reference.
